## Задание 1–2. report.sh

```
./report.sh <каталог> <ERROR|WARN> [--top N]
```

- Считает сообщения уровня по полю `$3`, имя модуля берёт из поля `$4` (`module=…`), сортирует по убыванию.
- `--top N` — только N первых строк.
- Нет аргументов, неверный уровень, несуществующий каталог, N не число → справка в stderr и код возврата 1.
- Пустой файл `25.log` и файл без ошибок `08.log` обрабатываются без особых проверок: `awk` просто не находит в них строк.
- Скрипт имеет shebang, права на выполнение и проходит `shellcheck` без замечаний.

## Задание 3. hello.py и strace

```
strace -f -o trace.txt python3 hello.py data/01.log
strace -f -c -o summary_py.txt python3 hello.py data/01.log
```

**Сколько всего системных вызовов:** 406 (из них 38 завершились ошибкой).

**Сколько относятся к чтению файла:** 6 вызовов (+1 `write` для вывода результата):

```
openat(AT_FDCWD, "data/01.log", O_RDONLY|O_CLOEXEC) = 3   # открыть файл
fstat(3, {st_size=19076, ...}) = 0                         # узнать размер
lseek(3, 0, SEEK_CUR) = 0                                  # текущая позиция
read(3, "2026-02-01 00:00:28 INFO ...", 19077) = 19076    # прочитать весь файл
read(3, "", 1) = 0                                         # конец файла
close(3) = 0                                               # закрыть
write(1, "19076\n", 6) = 6                                 # вывести ответ
```

**Почему остальные ~400 — накладные расходы интерпретатора.** Python — это программа, которая перед выполнением нашего скрипта должна запуститься сама:
- `execve`, загрузка динамических библиотек (`/etc/ld.so.cache`, `libc` и др.) через `openat` + `mmap`;
- выделение памяти (`brk`, `mmap`);
- импорт стандартных модулей (`encodings`, `site`, `os` и др.): для каждого — поиск по каталогам `sys.path` (`newfstatat`, `openat`), отсюда и 38 неудачных вызовов — Python проверяет пути, где модуля нет;
- настройка сигналов (`rt_sigaction`), получение случайного числа для хеширования (`getrandom`), проверка терминала (`ioctl`).

Ни один из этих вызовов не нужен для самой задачи — это цена запуска интерпретатора.

## Задание 4. Сравнение cat и python3

```
strace -f -c -o summary_cat.txt cat data/01.log > /dev/null
```

| Программа | Системных вызовов |
|---|---|
| `cat data/01.log` | 142 |
| `python3 hello.py data/01.log` | 406 |

**Вывод:** полезная работа (открыть → прочитать → закрыть) у обеих программ занимает несколько вызовов, но python3 делает почти в 3 раза больше вызовов. `cat` — небольшая скомпилированная программа на C: ей нужно загрузить только `libc`. Python сначала загружает и инициализирует интерпретатор. На маленьком файле накладные расходы запуска многократно превышают саму работу, поэтому для коротких задач выгоднее простые утилиты.

## Контрольные вопросы

**1. Почему нельзя обратиться к диску напрямую из пользовательской программы?**
Программа работает в **режиме пользователя**: процессор запрещает ей выполнять привилегированные инструкции и обращаться к портам и памяти устройств. Доступ к оборудованию есть только у ядра (**режим ядра**). Это защищает систему: ядро проверяет права доступа к файлам, не даёт программам мешать друг другу и портить файловую систему, а также скрывает различия между устройствами. Поэтому программа просит ядро через системные вызовы (`open`, `read`, `write`).

**2. Что дороже — вызов функции или системный вызов, и почему?**
**Системный вызов дороже.** Вызов функции — это переход внутри той же программы (несколько наносекунд). Системный вызов требует специальной инструкции (`svc` на ARM64, `syscall` на x86), переключения процессора в режим ядра, сохранения регистров, проверки аргументов ядром и обратного переключения; дополнительно действуют защиты от уязвимостей процессора. Это в десятки–сотни раз дольше. Поэтому программы читают данные большими буферами — чтобы делать меньше системных вызовов.
